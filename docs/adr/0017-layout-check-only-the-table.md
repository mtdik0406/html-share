# 17. ディレクトリを足したときの検査は、依存の向きの表に入っているかだけにする

- 日付：2026-11-23
- 状態：採用
- 置き換えたもの：[ADR 16](0016-layout-checked-against-configs.md)

## 状況

[ADR 16](0016-layout-checked-against-configs.md) は、コードのディレクトリの一覧と、検査の設定（`tsconfig.json`・`knip.jsonc`・`stryker.config.json`・`package.json` の網羅率と重複の対象）との食い違いを、`lint:repo` で見つけることにした。

その検査は、コード 100 行とテスト 190 行になった。設定ファイルの書き方（glob・script の引数・tsconfig の `-p`）を読み取るので、設定の書き方を変えるたびに直す必要があった。防ぐのは、直下にディレクトリを足すときの足し忘れで、ディレクトリを足すことはまれにしか起きない。

## 決定

- `pnpm run lint:repo` は、git が追跡する `.ts` のある直下のディレクトリが、依存の向きの表（`tools/lib/layout.ts` の `ALLOWED_IMPORTS`）か `test` にあることだけを確かめる
- 表に足すとき、検査の設定（`tsconfig.json`・`knip.jsonc`・`stryker.config.json`・`package.json` の網羅率と重複の対象）は手で合わせる。合わせる場所は、表の横のコメントに並べる
- 一覧は、ADR 16 のとおり表の 1 か所にだけ書き、`review:scope` の範囲もそれを使う

## 理由

- 表に入っていないディレクトリは、依存の向きが検査されない。この 1 つだけは、足し忘れても何も気づけないので検査にする
- 表に足す人は、横のコメントで合わせる場所を知る。足すことがまれなので、その手順を検査で守る費用のほうが大きい

## 捨てた案

- ADR 16 の突き合わせを残す：上の「状況」のとおり
- 検査をなくし、ADR 14 の手順だけにする：表に足し忘れると、そのディレクトリの import が黙って検査から外れる

## 結果

- 表に足したあと、設定に足し忘れても `lint:repo` は落ちない。そのディレクトリは型検査・未使用の検出・重複の検出・網羅率・変異テストから外れる
