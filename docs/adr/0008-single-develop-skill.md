# 8. コードを変える作業は、1 つの skill で始めから報告まで進める

- 日付：2026-11-21
- 状態：採用（テストの見逃しの扱いは 0018 で置き換え）
- 置き換えたもの：[ADR 7](0007-deterministic-quality-gates.md)

## 状況

ADR 7 では、作り終えた後のレビューと修正を `quality-review` の skill に任せた。コードを書く前の手順（振る舞いを決める・TDD）は別の skill に分けたが、2 つの skill が互いの手順を参照し合った。skill の本文は呼ばれたときにしか読み込まれないので、片方だけを使うと、参照した手順が読み込まれず、AI が推測で補う。

## 決定

ADR 7 の決定のうち、検査と変異テストについては変えない。変えるのは、レビューと修正を任せる skill だけ。

- コードを変える作業は、`develop` の skill 1 つで、振る舞いを決める → TDD → 検査 → レビュー → 修正 → 報告まで進める
- レビューだけを頼まれたときも同じ skill を使い、修正をせずに報告で止める
- テストが正しい理由で落ちたかは `pnpm run tdd:red`、テストの見逃しは `pnpm run review:mutants` の終了コードで決める
- 文書と skill が、ない script や skill を参照していたら `pnpm run lint:repo` で落とす

## 理由

- 始めから報告までが一続きの作業なので、1 つの skill にすれば、途中の手順が読み込まれないことがない
