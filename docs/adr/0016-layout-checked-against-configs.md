# 16. コードのディレクトリの一覧を 1 か所に置き、検査の設定との食い違いを lint:repo で見つける

- 日付：2026-11-22
- 状態：採用

## 状況

[ADR 14](0014-folder-layout.md) の「結果」は、新しいディレクトリを足すとき、依存の向きの表と検査の設定（`tsconfig.json`・`knip.jsonc`・`stryker.config.json`・`package.json` の網羅率と重複の対象・`review:scope` の範囲）を手で合わせて直す、とした。

一覧は 9 か所に重ねて書かれていた。足し忘れると、そのディレクトリのファイルは型検査・未使用の検出・重複の検出・網羅率・変異テストから黙って外れ、どの検査も落ちない。依存の向きの表に足し忘れると、そのディレクトリからの import は検査されない。

## 決定

- コードのディレクトリの一覧は、`tools/lib/layout.ts` の依存の向きの表（`ALLOWED_IMPORTS`）だけに書く。`test` を足したものを、コードのディレクトリ（`CODE_DIRS`）とする。`review:scope` の範囲もこれを使う
- `pnpm run lint:repo` が、次の食い違いを見つけて落ちる
  - git が追跡する `.ts` のある直下のディレクトリが、表にない
  - コードのディレクトリが、`tsconfig.json` の `include` になく、自分の `tsconfig.json` も持たない
  - コードのディレクトリが、`knip.jsonc` の `project` か、`lint:duplicate` の対象にない
  - ソースのディレクトリ（`test` と、入口だけを置く `bin` を除く）が、`test` の網羅率の対象か、Stryker の `mutate` にない
- 設定ファイルそのものは、一覧から作らない。ツールごとに書き方が違い（glob・引数・`include`）、作る処理のほうが壊れやすいため

ADR 14 の「結果」の 3 つ目（手で合わせる）を、この ADR で置き換える。

## 理由

- 足し忘れは、検査が黙って弱くなる形で現れ、人が気づく機会がない。AGENTS.md の「守らせたい規則は、文章より先に検査にできないかを考える」に従う
- 設定を一覧から作らず、食い違いを見つけるだけにすれば、各ツールの設定ファイルはそのツールの書き方のまま読める

## 捨てた案

- 設定ファイルを一覧から作る：上の「決定」の最後のとおり
- 文書に手順を書くだけにする（ADR 14）：足し忘れを止められない

## 結果

- 新しいディレクトリを足すときは、まず `tools/lib/layout.ts` の表に足す。`lint:repo` が、ほかに足す場所を挙げる
- `package.json` の script の書き方（`--test-coverage-include="..."`・`jscpd` の引数）を変えると、突き合わせが読めなくなり、食い違いとして落ちる
