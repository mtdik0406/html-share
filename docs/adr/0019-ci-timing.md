# 19. 変異テストの全体は main への push で流し、ブランチの push では速い検査と秘密値の検出だけを流す

- 日付：2026-11-23
- 状態：採用
- 置き換えたもの：[ADR 7](0007-deterministic-quality-gates.md) の「CI で毎回実行し」（[ADR 8](0008-single-develop-skill.md) が引き継いだもの）、[ADR 11](0011-review-and-mutation-scope.md) の「CI の `pnpm run test:mutation` は毎回全体を流す」、[ADR 18](0018-mutation-as-a-hint.md) の「変異テストのゲートは、CI の全体の実行のスコアの下限だけ」の実行の時機

## 状況

CI は、push と pull_request のたびに `pnpm run check` と変異テストの全体（約 25 分）を流していた。PR を使わず、ブランチの push の CI が成功してから main に fast-forward で取り込むので、取り込むたびに 25 分待っていた。PR を作ると、同じ検査が push と pull_request で 2 回流れた。

秘密値の検出（gitleaks）は、手元の `~/.gitconfig` の hook にしかなく、hook を通らないコミットは調べていなかった。

## 決定

- `check` のワークフローは、main を含むすべてのブランチの push で流す。タグの push と pull_request では流さない
  - `pnpm run check`
  - gitleaks で、履歴のすべてのコミットを調べる。見つけた値はログに出さない（`--redact`）。gitleaks の Action は使わず、版とチェックサムを固定したリリースのバイナリを照合して実行する
- `mutation` のワークフロー（変異テストの全体）は、main への push と手動の実行（`workflow_dispatch`）で流す。スコアが `stryker.config.json` の `break` を下回ったら落ちる
- 手元では、これまでどおり作業の最後に、変えたファイルだけを `test:mutation:scope` で流す（ADR 18）
- GitHub のルールセットやブランチの保護で、取り込みの条件を強制しない
- コードの脆弱性の解析は、GitHub の CodeQL の default setup に任せる（言語は javascript-typescript と actions、規則は default）。main への push と週 1 回、GitHub が流す。手元では流さない

## 理由

- 速い検査を push ごとに、遅い検査を取り込んだあとに回すと、待ち時間が検査の重さに見合う
- 変えたコードの見逃しは、変えたファイルだけを流せば分かる。変えていないファイルの結果は前回と同じ。変えたファイルだけでは見えないのは、テストを変えたことで、ほかのファイルの変異を倒さなくなった場合で、main への push の全体の実行が後から気づく
- 変異のスコアが下がっても、利用者に届く振る舞いは壊れていない。壊れた振る舞いは、ブランチの `check` が止める。後から直しても間に合う
- main への push でも `check` を流すのは、ブランチを通さずに main へ直接 push したときの歯止めにするため。ルールセットで強制しないので、この歯止めが要る
- gitleaks の Action は、既定で PR へのコメントと結果のアップロードを行い、トークンも要る。ここで要るのは、見つけたら落とすことだけ

- CodeQL を手元で流さないのは、データベースを作ってから解析するので重く、bundle の版を pnpm の外で管理することになるため。週 1 回の実行は、コードが変わらなくても GitHub が更新した規則で見つかるものがあるので残す

## 捨てた案

- 変異テストを push ごとに残す：取り込むたびに 25 分待つ
- 週 1 回の定期実行を足す：main が変わっていなければ、同じコードを同じテストで流すだけになる
- 作業の最後に、手元で変異テストの全体を流す：変えていないファイルの結果は変わらず、待ち時間が増えるだけ
- ルールセットで、main への push を検査の成功と fast-forward だけに絞る：起きていない問題に対して、GitHub の設定が増える
- main を `check` の対象から外す：同じコミットへの重複はなくなるが、main へ直接 push したときに何も流れない
- `pnpm audit` を CI に足す：脆弱性は Dependabot のアラートで知る（ADR 5）。足すなら、修正版のない警告の扱いを先に決める

## 結果

- テストを変えて、ほかのファイルの変異のスコアが下限を割ったときは、main に取り込んでから気づく。そのときは main の上で直す
- main に fast-forward すると、ブランチで通った同じコミットに、`check` がもう一度流れる
- gitleaks の版を上げるときは、`GITLEAKS_VERSION` とチェックサムを一緒に変える。ADR 5 と同じく、公開から 14 日たった版にする
- 誤検知で落ちたときは、`.gitleaksignore` に該当の指紋を足す。値そのものはリポジトリに書かない
- CI が走るのは push のあとで、リポジトリは公開している。CI が見つけたときは漏れたとみなし、その値を無効にするかローテーションする。コミットを止めるのは手元の hook の役目
