# 21. 取り下げた slug は、S3 から消す前に記録する

- 日付：2026-11-23
- 状態：採用
- 置き換えたもの：[ADR 3](0003-block-reuse-of-retired-slugs.md) の「`sync` で消した slug と時刻を残す」の時機

## 状況

`sync` は、S3 からページを消し終えてから、取り下げた slug を `.html-share/retired.json` に書いていた。消す途中で失敗すると（DeleteObjects の一部の失敗、消えたあとの通信の切断など）、記録まで進まない。S3 では消えていることがあり、そのページは次の同期の一覧に出ないので、二度と記録されない。

[ADR 20](0020-retention-and-archive.md) で、期限を過ぎたページの `retainUntil` を延ばして戻す使い方ができ、この穴を踏みやすくなった。

## 決定

- 公開をやめるページの slug は、S3 に書き込む前（置く・保管庫へ写す・消すのどれよりも前）に記録する
- `--dry-run` と、歯止めで止まった同期では記録しない

## 理由

- 記録が実際より多く残っても、その slug を 30 日使えないだけで、古い URL で別のページが見える事故は起きない。記録が欠けると、その事故を防げない
- 失敗した同期をやり直すと、同じ slug をその時刻で記録し直すので、30 日は実際に消えた時刻より前から数えることにはならない

## 結果

- 書き込みの途中で失敗し、ページが S3 に残っても、その slug は取り下げたものとして記録される。設定に戻すと、30 日は使えない
